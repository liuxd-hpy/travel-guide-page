# Step 0 输入交互问卷

用 `question` 工具分 **2–3 组**问完（每组可多问，`multiple: true` 用于多选项）。工具会自动附带"自己填"选项，用户没得选时可自填。
**关键参数不要替用户猜**：日期、时间、交通方式、人数必须问到。

---

## 第 1 组 · 行程骨架（必问）

| 问题 | 选项建议 | 追问 |
|---|---|---|
| 出发地 → 目的地 | 自填 / 常见组合 | 中间是否要停城市（多段行程） |
| **出发日期 + 具体时间** | 今天 / 明天 / 自填 | 「今晚 20:00」这类要给到钟点，用于算首日里程与住宿 |
| **返回日期 + 最晚到家时间** | 自填 | 「7 号白天就行」→ 记成 `7 日 18:00 前` |
| 总天数 | 自动算 + 让用户确认 | — |

⚠️ 日期决定一切：法定假日高速免费、门票是否需要提前抢、旺季限流、当天天气，都要按**实际出行日**核实，别沿用旧攻略的日期。

## 第 2 组 · 交通与预算

**主问题：交通方式？**

- **A 自驾**
  - 车型：油车 / 纯电（追问**续航标称**）/ 混动；是否需要写充电章节
  - **纯电必须追问「高速按几折算」**，不能只问标称续航 —— 折扣直接决定充电次数，进而改写整个时间轴：

    | 折扣 | 折算（标称 470 × 健康度 0.9 = 423） | 490km 单程 → 充电次数 |
    |---|---|---|
    | 7 折 | ≈ 296 km | 490÷296 = 1.7 → **2 次** |
    | 6 折 | ≈ 254 km | 490÷254 = 1.9 → **2 次**（且雨天要留余量） |
    | 5 折 | ≈ 212 km | 490÷212 = 2.3 → **3 次** |

    > 用户没给就默认 **6 折 + 雨天再 ×0.92**，并在正文写明这是保守估计。**不要只写标称续航。**
  - 同行人数（预算、订房、充电都要按人数算）
  - 是否有新手/长途经验（影响限速、隧道、疲劳提示的详细程度）
- **B 公共交通**（飞机 + 高铁 + 当地打车/包车）
  - 出发地是否有机场/高铁站，是否需要早班机/中转
  - 当地是否接受包车/打车（景区多时强烈建议包车）
  - 是否需要写"市内交通 + 景区接驳"章节
- **C 混合**（单飞单驾 / 单驾单飞）：先问哪一段自驾，再分别排两套交通方案

其他必问：

- **住宿档位**：经济 / 舒适 / 品质；每晚住市中心还是景区附近；是否必须带充电桩或停车
- **人数 & 是否需要人均预算分摊**（默认要）

## 第 3 组 · 内容与交付

- **必去景点**：用户列 / 由我推荐（推荐时给 4 必去 + 2 备选，各带门票和用时）
- **节奏**：轻松（每天 1 个点）/ 均衡（2 个）/ 紧凑（3 个）
- **美食**：口味偏好、忌口、是否忌酒（有些地方有"摔碗酒/米酒"等仪式）
- **拍照**：要不要「打卡机位 + 拍照姿势」章节（要就给 4 机位 + 3 组姿势）
- **交付形态**：电脑版 / 手机版 / 两版都要
- **图片来源**：是否要小红书实拍 + 笔记链接（默认要）
  - 用户说「不要 / 我自己提供图」→ **记录下来，全程不要问登录**

## 问完之后

先输出一屏《行程总览表》让用户确认，格式：

```
D0  10/1 20:00  赣州 → 吉安      220km 约2.5h   【宿吉安】
D1  10/2 06:30  吉安 → 恩施      800km 约10h    【宿恩施】
...
```

### ⚠️ 输出总览表前必须先做「日期 × 闭馆日」对撞

**这一步不做，整篇攻略会错。** 出发日是周几，直接决定博物馆/美术馆类场馆能不能进：

| 冲突 | 后果 | 处理 |
|---|---|---|
| 到达日撞上闭馆日（常见：**周一闭馆**） | 必去点进不去 | 顺延到下一个开放日，并**重算它的放票日期** |
| 顺延后放票时间已过 | 抢不到票 | 再顺延，或换备选景点 |

**连锁推导示例**：博物馆「提前 5 天、每日 20:00 放票」+ 到达日是 10/12（周一，顺延到 10/13 周二）
→ 10/13 的票在 **10/8 20:00** 开抢 = **今晚**，必须在总览表和正文里用醒目提示框顶在最前面。

同理核对：预约周期（提前 N 天）× 放票时刻（每日几点）→ **算出「哪一天几点必须动手」**，做成「抢票日历」表格放进第 05 章。

### 还要在总览表里显式说明

- **三条铁律的落地方式**（原图不裁剪 / 点图看大图 / 链接带 token 可直接打开）
- 若为纯电长途：**续航折算过程与每趟充电次数**（见第 2 组）

确认后再开始抓图和建站。

### ⚠️ 登录放最后：确认总览表之后、抓图之前才问

用户说「图片来源：小红书实拍」时**不要当场让对方登录**，那会打断前面三组问答的节奏。
正确顺序是：问完 → 核实 → 出总览表 → 用户确认 → **这时才自检登录态**，未登录才扫码。
代码见 `xhs-playbook.md` 铁律 0。

用户中途改需求时优先考虑重新问「图片来源」，这决定要不要碰小红书。

## 用户中途改需求时

- 改**日期** → 重排时间轴 + 重新核实门票/免费政策/预约窗口，图片可复用
- 改**交通方式** → 换 `references/outline.md` 里对应的 01/06/07/09 章内容，其余章节保留
- 改**人数** → 只改预算表、订房建议、电车充电分摊
